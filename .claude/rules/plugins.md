# Plugins — Inventory + Patterns

38 plugins. **Service plugins** expose named services — apps access via `self.require("name")`. **Enhancer plugins** inject providers into capabilities at startup (`priority=0`); capability falls back to next provider if plugin is absent/offline. No app code changes — "Graceful Enhancement" pattern. See `docs/DESIGN.md`.

## Disabling a plugin — four layers, strongest first

Pick the weakest layer that gets the job done; stronger layers exist so a permanent retirement can't be silently undone by a Store re-toggle.

| Layer | Where | Semantics | Use for |
|---|---|---|---|
| **Blacklist** | `plugins/BLACKLIST.toml` (repo) | Dropped during `discover()` — never enters the catalog, no `connect()` possible. Syslog warning on every attempt. No `force_load` escape. | Permanent retirement after damage. Today: `headroom`. |
| **Toml `enabled = false`** | `[plugins.<id>] enabled = false` in `emptyos.toml` (repo / per-machine) | Hard override that wins even over essentials. Plugin stays discoverable; loader skips `connect()` with a syslog warning. | "This machine does not load X" (repo-trackable intent). |
| **Store `disabled[]`** | `data/store/installed-plugins.json` (runtime state) | UI-toggleable via `/store`. Plugin stays installed but doesn't load. Essentials are immune. | Day-to-day "off for now." |
| **Store `installed[]` removal** | same file, runtime state | Plugin not in install set. | Never tried it, or actively uninstalled. |

Composition: `(installed − store_disabled) ∪ essentials − toml_disabled`, then filtered through the blacklist at discover time.

The toml `enabled` flag was decorative before 2026-05-26; the loader now honors it. If you want a plugin retired across every machine that pulls the repo, use the **blacklist**, not the toml flag.

## Obsidian is a dependency, not a given

EmptyOS uses the external markdown vault as its "hard drive" (`notes.path`) and Obsidian as the **vault viewer** — cross-platform desktop/mobile apps + the `obsidian://` URI scheme that every `EOS.noteActions()` link uses. The `obsidian` plugin registers service `viewer` and owns the URI templates; swap the plugin (or override its `uri_templates` in config) to switch viewers. Sync is independent — the vault is plain files, so Syncthing/git/iCloud all work without Obsidian Sync. Search runs through EmptyOS's own grep provider against the vault files — no Obsidian CLI dependency.

**Recommended companion — a diagram-fence renderer in the vault viewer.** EmptyOS itself never depends on one (fenced code is already part of the portable Markdown core per `docs/EOS-MARKDOWN-PROFILE.md`, and it renders as plain text with no plugin), but a diagram-heavy note (a KB `pattern`/`clause` note, an engineering write-up, an agent-authored spec) is far more legible with live PlantUML/Mermaid/Graphviz rendering in the vault viewer itself. [docu.md](https://docu.md) is a free/OSS (GPLv3), local-first Obsidian plugin that does this — no code integration point exists (it has no API/CLI, only editor plugins), so "integrating" it means installing it in the vault app, not wiring it into EmptyOS. Nothing in EmptyOS should ever assume it's present.

## A plugin in no tier ships nowhere

`release_filter.prune_snapshot` **deletes** every plugin absent from the
resolved tier union. So `release.toml`'s plugin list is "what reaches the
user" — not "what is enabled", which is the Store's job (`ESSENTIAL_PLUGINS =
{health}`; everything else arrives installed-but-off). Those two were being
conflated, and the tier list was acting as a second, invisible enablement gate.

Measured 2026-09-20: **15 of 38 plugins were in no tier at all**, and a further
one — `agent-runtime` — was tiered (`basic-engineer`, `dev`, `plekto`) but
absent from the **public union**, which is the distinction that matters. Eight
plugins were unreachable from apps that ship publicly:

| Plugin | Reached by | How it is declared |
|---|---|---|
| `agent-runtime` | rooms, forge | `[requires].services` — **hard**, `self.require` raises |
| `manim` | viz | `[requires].plugins` — **hard** |
| `markitdown`, `ocr` | reader | source `self.service(...)`, then raises on `None` — **hard** |
| `ocr` | worklog-capture | source `get_optional` — graceful |
| `meeting-capture` | braindump | source `get_optional` — graceful |
| `tailscale` | hub | source `get_optional` — graceful |
| `translate` | voice-assistant | `[requires].capabilities` — soft (LLM fallback) |

`_validate_dependencies` only WARNS to syslog, so each app loaded, went on
claiming the dependency, and the feature was dead until a user clicked it.

Nine moved into `standard`. `pronounce` went to **both** `english-learning`
and `englishos-cloud` — the second is the one that matters, because
`english-learning` has `delivery = "none"` and nothing extends it, while
`englishos-cloud` has a real Dockerfile, ships `dictionary`, and has no
`extends` of its own. Putting it only in `english-learning` would have changed
zero shipped artifacts while reading like a fix.

**Gated since**: `scripts/check_tier_plugin_reach.py` (preflight `apps` +
`release`, gate=True) resolves each tier's app set against its plugin union and
fails on any app naming a plugin its own tier drops. It reads the two manifest
fields that are a *declaration* — `[requires].plugins` and `[requires].services`
— and deliberately does not scan `self.service("x")` call sites, which reach
through `get_optional` as often as not and cannot distinguish a hard dependency
from a graceful probe. Waive a deliberate case with an inline
`# tier-plugin-reach: ignore <app> <plugin> — <why>` inside the tier's own
block, as the **whole comment** (a marker quoted inside a TOML string is
ignored — text-parsing a file the rest of the checker reads as TOML would
otherwise widen, silently muting a real finding). `demo` carries the one live
waiver, because that tier packages nothing: the live demo ships from
`targets.public`.

**It guards two of the eight rows above** — `agent-runtime` and `manim`, the
only two declared in a manifest. Measured against the pre-fix tree: 18 triples
over 8 tiers, 2 distinct plugins, 3 apps. The other six were hand-found and
stay **unguarded**, so a future trim of `standard`'s plugin list that drops

Closing that would need the **capability edge** — `[requires].capabilities`
against the plugins enhancing it. Seven capabilities register with an empty
built-in chain (`speak`, `listen`, `pronounce`, `draw`, `animate`, `model`,
`artifact`), so a plugin is their only provider — except `model` and `artifact`,
which apps provide (robot-modeller, viz) through registration declared nowhere.
The general check therefore fires on a healthy tree. Build it when app-side
provider registration becomes declarative; until then `pronounce` is the one
live case and is placed by hand.

**Still deliberately untiered (6)** — each ships nowhere on purpose:

| Plugin | Why |
|---|---|
| `footage` | the capability has **zero** consumers; shipping it would add a dark provider chain |
| `tailscale-serve` | write-side companion to `tailscale`; no app names it |
| `android-control` | the operate executor's Android sibling; `macro-studio` is a Windows-macro product |
| `claude-design` | connector to a specific third-party design surface |
| `gmail`, `youtube` | credentialed connectors bound to an authorized account, not generic product surface |

Adding a plugin to a tier is cheap and reversible; leaving a shipped app's
declared dependency out of it is not, because the failure is silent.
