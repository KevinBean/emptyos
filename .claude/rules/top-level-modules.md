# Top-Level Modules — why these live in `emptyos/` and not `emptyos/sdk/`

Moved out of CLAUDE.md § Key Files (2026-09-25) to keep the always-loaded
instruction set under budget. CLAUDE.md keeps one line per module.

**The shared reason.** Importing anything under `emptyos/sdk/` runs that
package's `__init__` and pulls in `base_app`, and the kernel never imports
`emptyos.sdk` at module level. A helper both the kernel/runtime and the SDK need,
or one a kernel-free module needs, therefore lives top-level and stays
stdlib-only. Keep it that way when you edit one.

- `emptyos/nethost.py` — `canonical_hostname` + `host_is_loopback_or_private`. Both the kernel (`capabilities/consent.py`) and the SDK (SSRF gate, agent tools) need it. Canonicalise a host through this before comparing it to loopback/private ranges — `urlparse` does not, and `0x7f.0.0.1` / `127.1` / `127.0.0.1.` all reach loopback in the client that opens the connection.
- `emptyos/frontmatter.py` — the frontmatter block: `fm_end` (where it ends), `parse_frontmatter`, `strip_frontmatter`, `set_frontmatter_field`. Both the SDK and the runtime (`vault_index`, the read path behind `vault_query`) need it. **It exists because there used to be two of it**: this and `vault_index._parse_fm` were near-verbatim copies and drifted three separate ways (empty scalars typed by their *position* in the block; quoted empties; where the block ends), each found only after the previous was fixed. All three helpers call `fm_end`, so the parser, the body splitter and the field writer cannot disagree about the boundary. One syntax → one type: `key:` and `key: ""` read `""` anywhere in the block, `key: []` reads `[]`.
- `emptyos/basepath.py` — `resolve_under_base(path, base)`: absolute paths pass through, relative paths join the base, no base leaves them relative. The kernel's own `capabilities/providers/filesystem.py` needs it. **It exists because there were five of it**: both filesystem providers plus the `markitdown` / `ocr` / `legacy-doc` read providers each carried the body verbatim, three under a comment promising they "mirror FilesystemReadProvider" — which a comment cannot enforce. Mutation testing found two of its three branches are **explicit rather than load-bearing** (`Path.__truediv__` already discards the left side on an absolute right side; `Path("")` is `Path(".")`), so no test pins them and none can — that is stated in the docstring so nobody deletes them as dead code. The branch that IS observable and must be protected: it never calls `Path.resolve()`, so it works on paths that do not exist yet (what the *write* provider needs) and never binds a relative result to the caller's cwd. `routes_vault.py` is deliberately NOT a consumer — it resolves **and confines**, a different function.
- `emptyos/fieldspec.py` — the calculator-declaration checker: `validate_declaration` (closed unit table, closed group table, duplicate input name, duplicate output name, `derived_from` resolves) + `render_domain`. Both consumers are pure `spec.py` declaration modules imported by daemon-free test suites. It extracts the **behaviour, not the record**: `trust-loop` and `cable-bonding` keep their own `FieldSpec`, because their positional orders transpose `label`/`unit` across 63 positional declarations and `group`/`slot` are not the same question. Consumers: `apps/public/standard/trust-loop/spec.py`, `apps/extension/engineering/cable-bonding/spec.py`.
- `emptyos/composite_score.py` — weighted composite scoring: `normalize_values` (minmax / mid-rank / Hazen quantile / z-through-normal-CDF, with a `direction` flip) + `composite_score` (relative weights, arithmetic|geometric, explicit `drop`/`renormalize` null policy) + `dimension_rollup`. `work-fit/scoring.py` declares itself kernel-free (measured: 374 modules via the SDK vs 4). Three edges are load-bearing and each is a *silent wrong answer* if lost: a constant field normalizes to **0.5, not 0.0**; the geometric mean needs `GEOMETRIC_FLOOR` or one min-max-minimum component ties every subject at zero; and missing-component handling is a **caller policy**, not a default. Arithmetic is scale-free (`scale=1.0` keeps native units) because rescaling through 0..1 and back is not value-preserving — it shifted 59/2000 work-fit assessments by 0.1. Geometric *requires* 0..1 and refuses otherwise. Consumers: `apps/personal/work-fit/scoring.py`,`apps/personal/{briefing,hub-life}` (`dimension_rollup`).
- `emptyos/headless.py` — the headless-process console guard: `install_headless_subprocess_guard()` (first line of `eos start`) wraps `subprocess.Popen.__init__` so that **a process with no console never lets a child open one** (`CREATE_NO_WINDOW` added unless the caller chose a console intent), plus `no_window_flags()` for a call site that must hold without the guard. It must run before the kernel exists. **It exists because this box hard-froze three times** (2026-08-01, 08-15, 09-06) with a fourth storm caught live the same night: a daemon respawned `DETACHED` by the watchdog has no console at all, so Windows allocated a *visible* Windows Terminal tab for every `git` it spawned; Event 4688 traced a quarter of the 09-06 storm's console clients to that daemon's pid, dominated by `git rev-parse` from the polled `api_status`, and the tabs held ~20 GB until commit ran out. A `CREATE_NO_WINDOW` process (sandbox member) is *not* this case — it has a hidden console its children inherit — which is why `has_console()` probes `GetConsoleCP`, not `GetConsoleWindow`. About a hundred spawn sites carry no flag; flagging each is a losing race, so the rule is set once per process.
- `emptyos/speechlang.py` — `detect_speech_language`: the single rule deciding `zh`/`ja`/`en` for TTS **voice and provider** selection. `sdk/tts_cache.py` states in its own docstring that it stays light (measured: 416 modules via the SDK vs 43). **It exists because there were three of it, and they disagreed**: the edge-tts plugin's, `BaseApp.speak`'s provider routing, and `plugins/voice-api`'s — the last still unmerged and carrying no `ja` branch at all. It keys on **hiragana**, not all kana: Chinese never uses hiragana but does quote katakana, so 他喜欢吃拉面ラーメン read as Japanese at 40% and escaped the Chinese routing back to the provider that garbles it. Known limit: zero-hiragana text is indistinguishable from Chinese — a caller holding Japanese should pass `language=`. Consumers: `emptyos/sdk/utils.py` (re-export), `BaseApp.speak`, `emptyos/sdk/tts_cache.py`, `plugins/edge-tts`.
