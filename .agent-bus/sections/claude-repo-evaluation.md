

When evaluating an external repo/tool for borrowing, **first check for a closed verdict** — run `python scripts/check_borrow_verdict.py <repo-or-library-name>` (exit 1 = a verdict already exists in `docs/OPEN-SOURCE-BORROWING-PLAN.md` / `docs/DEFERRED-WORK.md`; read it and stop, don't re-derive it). Then **ground every claim against the real repo/source before giving a verdict** — read the actual code; never characterise it from memory or the README alone. Record the **build / borrow / build-nothing** decision (and *why*) to memory docs so it isn't re-litigated. The disciplined form is the `/eos-repo-extract` skill (smallest honest abstraction, ≥2 real consumers); the standing verdict log is `docs/OPEN-SOURCE-BORROWING-PLAN.md` plus the `*-borrow-verdict` memories. Any verdict that **defers** a substantive feature also gets a one-row entry in `docs/DEFERRED-WORK.md` — its build/deploy trigger + reference repo — so a later session can find it when the need arises; the periodic readiness recheck ("has a trigger fired?") lives in the `eos-insights` skill.

This grounding generalizes: **any conclusion drawn by reading across many sources** — insights, audits, "state/trajectory of X", "why does Y recur", strategic reviews — follows the **deep-research method** (`.claude/rules/deep-research.md`): baseline → first-pass → gap-pick → deep-read primary sources → adversarially refute → grade evidence. Reach for it whenever being *confidently wrong* would be costly; skip it for one-read lookups. It's doctrine, not a tool — the judgment is the value, so don't try to automate it.
