# EmptyOS UI Audit — 2026-08-16

Scope: full pass (public + extension + personal), mechanical + structural, audit-only.
Rendered phases (0c readability, 0d affordance) **not run** — they need the live daemon.

## Verdict

**The tree is clean.** 17 gated checks pass, the graduated structural scanner is
clean, and after applying every documented carve-out there is no public-facing
drift that justifies a migration sweep.

Two things are worth acting on, and neither is a per-app migration:

1. A **tooling blind spot** in `scripts/check_ui_structure.py` (S-2 measures only
   inline `<style>`, so any app following `.claude/rules/multi-module-apps.md`
   and extracting its CSS to a sibling file becomes invisible).
2. One **gitignored personal app** (`cable-sheath`) that never adopted the design
   system at all.

### DL-2 — the count is a doc question, not a migration

Distribution: `3px` 167 · `5px` 140 · `7px` 93 · `9px` 83 · `1px` 80 = 68% of hits.
`1px` is almost always a border/hairline and must **not** be rounded to 0
(SKILL.md warns to round *up*). The odd-number band is exactly what DL-2's own
text names as "the common offenders", so this is genuine-but-low-value drift —
nobody perceives 3px vs 4px. Not worth a sweep; migrate on touch.

### Finding: S-2 has a sibling-CSS blind spot

`STYLE_BLOCK_RE` matches only inline `<style>…</style>`. **22 of 250 pages** are

| 519 | 0 | `personal/jobs/pages/index.html` | yes (documented) |
| 439 | 0 | `personal/music-studio/pages/index.html` | **no** |
| 315 | 0 | `personal/speaking/pages/index.html` | **no** |
| 248 | 0 | `projects/pages/{index,workspace}.html` | **no** |

Roughly half are documented islands and exempt anyway, so the *impact* today is
narrow. The reason it still matters: `.claude/rules/multi-module-apps.md`
actively encourages extracting page CSS/JS to siblings, so **the blind spot
widens every time an app follows the recommended convention.** The scanner will
go quietly blind as adoption grows — the failure mode `.claude/rules/audits.md`
calls a vacuous pass.

It is **not** a brand island and **not** a runtime island: it declares its

That is a coherence defect, not a readability one; it will not be unreadable.

**Priority caveat, stated plainly:** `cable-sheath` is gitignored
(`.gitignore:66 apps/personal/`) with **0 tracked files**. It never reaches a
public release or the demo. Despite owning 68% of the raw count, its blast

## Recommended scope

Ranked by value per unit of risk:

1. **Close the S-2 blind spot** in `check_ui_structure.py` — count sibling
   `pages/*.css` alongside the inline block. Durable; prevents silent decay.
   *(This is the only finding that compounds.)*
2. **`check-attr-escaper.py --fix`** — 3 sites, one file, mechanical.
3. **`cable-sheath`** — either adopt the design system (drop `sheath.css`'s
   palette onto theme tokens, swap the `prompt()`) or, if it is deliberately a
   standalone calculator, declare it a brand island and add it to the table so
   it stops dominating every future audit. **Declaring it is the cheaper honest
   answer** if it is never meant to theme.
4. **Long tail** — 62 DL-1 across 27 apps, mostly `#ef4444` where `var(--danger)`
   exists (`speaking.css:305` literally writes `border-color:#ef4444;
   color:var(--danger)` in one rule). Migrate on touch, not as a sweep.

**Explicitly not recommended:** any DL-2/DL-3/DL-4 sweep (768+ sites, imperceptible
payoff, real regression risk on `1px` borders), and any new shared helper.

## Applied this session

### 1. Closed the sibling-CSS blind spot — `scripts/check_ui_structure.py`

`read_page_sources()` (renamed from `page_files` — see item 4) now reads inline
`<style>` **plus** sibling `pages/*.css`. The bug
was deeper than the S-2 stat: that same `css` string feeds `fingerprint()`, so an
app hand-rolling `.modal-bg` / `.toast` / `.hero-card` in a sibling file scored
`none` on those cells — and since `is_outlier` requires `in_use >= 3`, **the rule
could never fire for it.** S-2's stat now measures total page CSS, not the first
inline block.

Verified in both directions per `.claude/rules/audits.md`:

- **Green:** tree still clean (171 pages, 0 outliers) — no new false positives.
- **Red:** a synthetic page with no inline `<style>` and hand-rolled component CSS
  in a sibling file is now correctly flagged; a private `:root` namespace in a
  sibling file is now correctly detected as an island.
- Both pinned as permanent selftest cases (11 → 13).
- Island detection corrected **7 → 8** — one app's private tokens live in a
  sibling file and were previously unseen.

### 2. `check-attr-escaper.py --fix`

3 sites in `trust-loop/pages/trust-loop.js`, `esc(` → `escAttr(` in attribute
context. Correctly left `esc(f.label)` alone (HTML text context, not an
attribute). `node --check` clean; `test_unit_trust_loop*.py` 50 passed.

**Result:** `preflight --scope ui` → 17 checks · 0 FAIL · **1 warn** (was 2).

### Correction to the `cable-sheath` finding above

The report says the structural scanner "passed" `cable-sheath`. That is wrong in
a way worth recording: `_scan_pages()` iterates `git_tracked()`, and
`cable-sheath` has **0 tracked files**, so the scanner never saw it at all.

The two facts are independent and both hold:

- The sibling-CSS blind spot was real (22/250 pages, red direction proven) and is
  now fixed.
- `cable-sheath` was invisible for a *different* reason — it is gitignored.

So closing the blind spot does **not** bring `cable-sheath` into scope. Any
gitignored personal app remains outside every `git_tracked()`-based scanner by
design. That is a defensible boundary (personal apps never ship), but it means
the "68% of DL-1" headline describes code no scanner will ever gate.

### 3. `cable-sheath` migrated onto theme tokens

| | before | after |
|---|---:|---:|
| DL-1 in `sheath.css` | 83 | **0** |
| DL-1 in `sheath.js` (live UI) | 39 | **0** |
| DL-1 in `index.html` | 9 | **0** |
| DL-6 native dialogs | 1 | **0** |
| `var(--*)` usages in `sheath.css` | 6 | **136** |

What changed:

- **`sheath.css`** — 130 lines, colour only. Layout, spacing and sizing
  untouched. Surfaces → `--bg` / `--bg-card` / `--bg-surface`; text →
  `--text` / `--text-heading` / `--text-muted`; borders → `--border` /
  `--border-strong`; the two header blues → `--accent` plus a
  `color-mix(… var(--text))` deepening that darkens on light themes and lightens
  on dark; status colours → `--success` / `--warning` / `--danger`; their tints →
  `color-mix(… var(--bg-card))`; `white`-on-vivid → `--ink-on-vivid`.
- **`sheath.js` + `index.html`** — 69 lines of inline-style hex in live-UI
  template strings and `style=` attributes.
- **DL-5** — three all-caps meta labels had 0.04–0.05em tracking (≈0.5px at 11px,
  under the ≥1.5px rule). Now `var(--tracking-meta)`.
- **`prompt()` → `EOS_UI.formModal`** — `formModal` is async, so `saveProject()`
  splits into a modal call plus `downloadProjectFile(description)`.

**Deliberately NOT migrated:** `exportReport()` (lines 1719–2270) builds a
standalone `<!DOCTYPE html>` compliance report. It is its own document with no
`theme.css` inheritance, so its palette must stay hardcoded — the
string-concatenated-document carve-out. A marker comment now sits above it so
future audits stop re-flagging its 13 hex.

#### Baseline measurement — the migration did not fix a readability defect

Rendered readability, `check_readability.py --app cable-sheath`, 10 themes:

| | fail | warn |
|---|---:|---:|
| before | **0** | 76 |
| after | **0** | 76 |

This confirms the "coherence defect, not a readability one" call made earlier.
The app hardcoded *both* surface and text, so it was internally self-consistent
and always passed contrast — it simply ignored the theme. The rendered audit
cannot see that class of defect at all; only the static DL-1 scan could.

Worth recording as a limitation: **a theme-invariant app passes the rendered
readability audit.** The audit measures contrast within a page, not whether the
page honours the theme.

One speculative follow-up was tried and reverted: moving `.btn-outline` from
`--text-muted` to `--text` on the theory that an interactive control shouldn't
sit in the muted band. Measured 76 → **82** warns, so it was reverted rather
than shipped.

### 4. Simplify pass — the three flagged items

**Buttons migrated to `.eos-btn*`.** 19 class attributes across `index.html` +
`sheath.js`; the local `.btn` / `-primary` / `-success` / `-sm` / `-outline` /
`-danger-outline` / `-large` rules deleted (they restated the shared classes).
Only `.btn-group` / `.btn-run-row` (layout) and `.ecc-item .btn-remove-ecc`
(bare icon button) stay app-local.

| | before | after |
|---|---:|---:|
| structural `btns` cell | `hand` | **`EOS_UI`** |
| `eos-` class adoption | 1/429 | **56/428** |
| `sheath.css` lines | 642 | **602** |
| readability warns (10 themes) | 76 | **65** |

Density was the risk: the old `.btn-sm` was `4px 9px` and `.eos-btn-sm` is
`7px 14px`. Deviating would have re-introduced the drift, so the shared sizes
were taken and the result verified rather than assumed — affordance scan
**0 fail / 0 warn**, sidebar `scrollWidth == clientWidth` (no overflow), and
screenshots in light + dark confirm layout.

Worth noting against the reverted experiment above: adopting
`.eos-btn-secondary` achieved the *same intent* (a non-muted control label) and
moved warns 76 → 65, where the hand-rolled attempt moved them 76 → 82.

**`page_files` renamed to `read_page_sources`** in `check_ui_structure.py` —
`scanner_lib.page_files` is a *tree walker* returning paths, and two scanner
modules exporting one name with two shapes is a trap. `_scan_pages` deliberately
still does **not** adopt `scanner_lib.page_files`: it walks `git_tracked()`, so
switching would move the denominator 171 → ~250 and start reporting on
gitignored personal apps — a behaviour change, not a cleanup.

**`tests/personal/test_sheath_voltage.py` — 7 dead UI tests removed.** They
targeted `cable/pages/sheath.html`, which no longer exists (the cable ←
sheath-voltage merge was later reversed; sheath is its own app again). Two
failed — but **five vacuously passed**, loading a 404 that has no JS and then
asserting "no JS errors", so they read as green coverage while testing nothing.
That surface is already covered by `test_cable_sheath.py`. The 4 API tests stay
(`/cable/api/sheath/*` is live, verified 200) and three of them had
`assert resp.status_code < 500 or True` — a tautology asserting nothing — now
tightened to a real assertion.

Also fixed `test_cable_sheath.py:106`: `assert_no_js_errors(page)` passed the
Playwright `Page` where the helper wants the error **list**. A `Page` is truthy,
so it skipped the early return and raised `TypeError` on iteration — the
assertion never ran.
