# Blender 動畫製作指導

適用：MV 原生動畫、動態歌詞、紙張與物件動畫、2.5D／3D 場景、生成素材合成。整理日期：2026-09-13。

這是既有 `tool-blender-comfyui-video` 製作流程的專門參考，不另建生成管線。影片的故事與風格由當前歌曲決定；Blender 負責可重現的空間、動作、光影和合成。本文的參數是需要按鏡頭測試的選擇，不是通用美學預設。

## 1. 每個鏡頭先定五件事

1. **觀眾要看懂什麼？** 寫一個主要事件，例如「標籤從玻璃揭離」，不要同時塞入多個表演。
2. **哪個系統控制什麼？** 明定人物動作、攝影機、背景、光影的控制來源。精確動作交給 rig／幾何／關鍵幀；生成影片可作已驗收素材，但不能假定能精確服從轉身或接觸要求。
3. **實際空間是什麼？** 是前景疊圖、貼在場景表面、2.5D 投影，還是完整 3D？只建鏡頭需要的深度，也如實標示限制。
4. **動作時間是什麼？** 對照選定原曲，記錄起點、主要重音、可讀停留、終點及剪輯餘量。
5. **如何判斷失敗？** 例如滑步、紙背佔據閱讀時間、接觸陰影游離、攝影機露出貼圖邊緣。先寫可見現象，再做樣片。

## 2. 選擇控制方式

| 問題 | 優先考慮 | 需要驗證的限制 |
|---|---|---|
| 剛體移動、燈光、鏡頭 | 關鍵幀與曲線 | 不要所有通道同時使用相同 ease；接觸和恆速段可能需要不同曲線 |
| 可指定的捲紙、呼吸、局部變形 | Shape Keys 或參數化幾何 | 輪廓、UV、法線與中間形態都要檢查 |
| 大量規律或程序性物件 | Geometry Nodes 等程序方法 | 不讓程序的規律壓過音樂節奏；保留可導演的控制參數 |
| 轉身、步行、伸手 | 骨架、姿勢、IK／約束 | 腳底接觸、重心和物件接觸要逐段看，不能只有漂亮端點 |
| 布料、碰撞、自由落體 | 模擬，必要時配合約束 | 烘焙並保存快取；模擬的自然結果未必符合歌曲時間 |
| 平面場景上的文字／圖像 | 平面追蹤、角點透視、遮罩 | 追蹤座標與交付尺寸一致，穿過人物時需正確遮擋 |
| 需要遮擋或鏡頭視差的場景 | 3D 幾何、分層或受限投影 | 深度圖不能恢復背面；鏡頭一動就要驗證破洞與拉伸 |

方法沒有通過短樣片前，不把「節點已安裝」或「程式能執行」當作工作流已成立。

## 3. 先做動作，再做外觀

採用四次逐步完成的同一鏡頭，不建立四條互不相干的時間線：

1. **Blocking**：簡單形體、固定鏡頭、清楚的關鍵姿勢。先確認構圖、路徑、動作事件及方向。
2. **Motion**：補中間過程和速度曲線，處理準備、主動作、接觸、緩衝、停穩。節奏來自錄音與表演，不能一律變成 slow motion。
3. **Look**：材質、燈光、陰影、字體與背景整合。控制代理物件不能僅換材質就當作完成資產。
4. **Composite**：合成、遮罩、色彩、輸出。回到上下鏡頭和原曲，確認新增效果沒有搶走表演。

先檢查輪廓與運動軌跡，必要時用無材質預覽。端點正確不代表路徑正確：手可能穿過枝葉、腳可能滑行、轉身可能翻面。每次修剪仍須保留觀眾辨識動作的關鍵階段。

鏡頭紀錄沿用現有 shot-state ledger：選用幀區間、畫面行進方向、身體朝向、視線、首尾姿勢、著地狀態、感知速度、鏡頭移動、道具狀態與剪輯意圖。裁切或鏡像後重新標記；不能只按 prompt 填表。

## 4. 紙張貼上與揭下

### 幾何與接觸

把紙分成「仍貼住的區域、正在彎曲的捲邊、已離開表面的區域」。捲邊沿紙面前進，未揭區域保持附著；完全離開後才進入自由離場動作。

可先使用沿彎曲方向充分細分的網格，以參數控制揭離進度、捲曲半徑、揭角與離場位移。增加細分直到交付尺寸的輪廓足夠平滑，不照抄固定網格數。需要指定進度時，先測可控制的變形；只有自由飄動確實需要時再加 cloth。

文字與紙面共用穩定 UV／變形關係。正背面分開設計，紙背可以是暖白、纖維或黏膠質感；材質顏色、光線造成的變暗和不透明度是三個不同控制，不能混用。近距離側面需要厚度時才增加相應幾何，並檢查相交。

### 時間設計

每張標籤以秒或歌曲提示制定節奏，再轉成當前 fps 的整數幀：

`貼入 → 正面穩定可讀 → 揭離 → 離場`

- 貼入不能只有淡入；揭離不能只是整張板子翻轉。
- 閱讀時間只計正面可辨識的部分，不計背面或嚴重彎曲期。
- 先確保閱讀與動作有足夠時間，再決定歌詞拆分／合併。
- A 揭下時 B 可在另一位置貼上，讓視線有去向，避免兩個視覺重音同時搶焦點。
- 呼吸主要放在可讀停留期，以輕微曲率、尺度或傾斜變化測試，不預設每張都同幅同相。貼在牆上的紙不能整張上下浮動而失去接觸。
- 若標籤太短，先減少動畫複雜度或合併語意，不把進出動作一味加速。

### 光影

優先用紙的法線、粗糙度與燈光產生捲邊高光。藝術性補光可以使用，但需與場景光向一致，不能讓紙意外像自發光螢幕。

接觸部分陰影貼近紙面；離面區域的陰影方向、距離和柔軟度應與光源及承接面相容。投影陰影網格適合受控的平面合成，不能當作任意 3D 空間都正確的陰影方案。

驗收一個完整樂句，包含兩張標籤交接；同時看正常播放、慢速診斷和正背面關鍵幀。正常播放才是動作是否自然的最終判斷。

## 5. 場景與合成

- **平面素材**：先做無動作基準渲染，核對原圖比例、構圖、色彩與邊緣。不要把生成圖片叫作可編輯 3D 場景。
- **攝影機**：先固定構圖再添加有敘事用途的運動。相機位移必須有足夠幾何或分層支援；大幅環繞不是一張深度圖就能保證。
- **表面貼附**：記錄承接面、錨點、縮放、透視、層級和遮擋者。看最易漂移或遮擋的中間幀，不只看首尾。
- **透明疊層**：核對 alpha 處理與邊緣，分別看疊層本身和最終合成。黑邊、矩形邊界、半透明重影都不能靠縮圖驗收。
- **色彩**：選定並記錄色彩管理；比較相同設定下的素材與渲染。資料貼圖如遮罩、深度、法線不當作普通顏色解讀。不要把本片使用的 Standard 視圖變成所有項目的預設。
- **環境效果**：霧、雨、彩虹、反射等先確認空間位置、遮擋與歌曲功能。獨立運動不等於整片漂移；水面反射需與接收表面相容。

## 6. 渲染與恢復

1. 先固定原曲、fps、幀區間、解析度比例與色彩管理；局部樣片和交付使用同一時間基準。
2. 預覽可降低尺寸與採樣，但保持原來的動作時長。品質參數針對實際引擎設定，不以程式裡出現參數名稱作生效證據。
3. 長任務優先考慮可續算影格序列，最後再封裝；需要高動態範圍或後期通道時選合適的中間格式。估算磁碟用量，避免無理由輸出大量通道。
4. 保存可重現的 .blend、素材來源與 hash、設定、字體／貼圖依賴，以及實際使用的模擬快取或驅動程式。新程序重新開啟後測幾個非連續幀，檢查是否依賴未保存的互動狀態。
5. 中斷後先查缺幀和錯幀，再只補缺失區間。不能只因檔案存在就認為整片完成。
6. 最终核對幀數、尺寸、完整解碼、音訊起點與同步、尾音、黑幀和非預期停格；另外觀看全片的動作與情緒。

## 7. 《算了吧》實作留下的邊界

已讀取的 `recut-v80/lyrics-design.py` 使用細分網格、絕對 Shape Keys、正背面材質、投影陰影，以及獨立的呼吸關鍵幀。這證明方法已實作，不代表其所有參數都值得繼承：

- 固定貼入 9 幀、揭離 14 幀是該腳本的選擇，下一首要重新按閱讀與樂句決定。
- 固定尺度呼吸和陰影跟隨不是所有承接面的合理解法，場景貼附需另外檢查。
- 以法線驅動暖色 emission 是藝術性捲邊補光，並非真實光源反射的保證。
- 腳本使用 EEVEE，同時存在 Cycles 設定；不能僅看那些 Cycles 參數就宣稱 EEVEE 採樣已正確配置。
- 既有 Blender skill 記錄過 Blender 5 逐幀直接修改 mesh 的 GPU 刷新問題。只有採用相同更新路徑時才針對版本驗證相關刷新呼叫，不把它們加入所有 Shape Key 動畫。

這些是應用邊界與回歸檢查項目。本次整理未重新渲染樣片，不宣稱新動畫方案已通過。

### 7b. 《不可說》書頁真歌詞合成（2026-09-14）

生成的紙頁帶假字，影片模型也寫不出真字。這次先清掉假字得到乾淨底圖。Blender 5.0 以無頭模式運行：正交相機配 emission 底板，四角單應性把轉成 mesh 的文字頂點映射到紙面透視，歌詞一律從發佈字幕檔讀入（斷言 36 句）。紙面本身不動，所以文字沒有做動畫：靜態渲染用 ffmpeg 軟邊遮罩疊在 Flow 動態片上，紙面內保留精確手稿，紙外保留流動的光。

Kevin 的三輪修正是版面問題，不是技術問題：先要寫完整歌詞，再嫌紙面太空，最後要求「要有美感」。對應做法是兩句並一行、放大字高、每三行多留一段空，雙頁與近景用同一套分行。

邊界：只適用於紙面固定的鏡頭；emission 文字不受光；像素角點綁定底圖原尺寸；`pack_all()` 會把系統字體打包進 .blend。完整記錄與檢查項見 `tool-blender-comfyui-video/references/lyric-surface-composite.md`。

## 8. 每次樣片只交付四項

1. 一段帶原曲上下文的正常速度影片，必要時加同條件 A/B。
2. 一句話描述想表達的動作，以及它是否可讀。
3. 具體缺陷與決定：接受、調整、放棄或證據不足；技術與藝術結果分開。
4. 可接續的 .blend、素材與設定紀錄；若只是 blocking，明確標為代理預覽。

當動作已成立，才增加材質與效果；當新增複雜度沒有帶來可見改善，就回到較簡單版本。
