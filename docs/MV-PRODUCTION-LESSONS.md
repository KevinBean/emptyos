# MV 製作經驗總庫

整理日期：2026-09-26（統一重編；前身為 2026-09-12 起的《算了吧》經驗文件）。

**這是所有 MV 的單一經驗來源。** 開新 MV、審片、重剪、救回、交付之前先讀 §A–§C；遇到具體問題查 §D 主題索引；想知道某條規則從哪次失敗學來，看 §F 案例。各階段怎麼做、交什麼、誰批准，看 [MV 製作指南](MV-PRODUCTION-GUIDE.md)（入口 skill `creative-mv-director`）。`creative-mv-generator` 與 `creative-mv-art-director` 兩個 skill 開工前都要求先讀本文件。

證據標記：行內 `專案:階段:鏡頭:次數` 對應 vault 的 MV 庫 `10_Projects/YouTube-Music-Channel/library/attempts.jsonl`；可重用的提示詞寫法及其成功／失敗數在 `library/patterns/`；失敗代碼在 `library/failure-codes.md`。每首歌的原始記錄（CURRENT、FAILURE-CASE、RETROSPECTIVE、成本賬）在各自的 MV 資料夾，§F 列出路徑。

**維護規則：** 每支 MV 交付或放棄後，在 §F 加一個案例（結果、做法、成本、3–10 條教訓附證據），並把新規則併入 §B–§D；與舊規則衝突時寫進 §E，說明新規則與適用範圍，舊文不刪、在原處註明「已被取代」。

## §A 十五條核心原則（按重要性）

1. **先有情緒命題，再有素材。** 一句話的情緒命題＋一條主線，先剪 20–30 秒帶歌樣片，用戶說「有感覺」才擴大生產。（已被 §E15 補充：樣片從全長活母帶 v0 取，v0 先於任何付費影片。）換地點不等於推進故事。（說得太急、Spark、不可說）
2. **每個鏡頭寫出存在理由：讓觀眾感到或理解什麼。** 答案只是「讓人物走到下一個位置」，就用聲音、遮擋、省略或直接切鏡。（說得太急 V17-M02）
3. **生成模型的弱項不要當主事件。** 人與剛體的互動（開門、上床、上車、穿衣、起身坐下）、全身跳躍與轉身、複雜的腿部舞步，一律避開或改用 Blender／後期。（說得太急、Spark、算了吧、Log Out）
4. **唱與不唱在腳本階段分流。** 不唱的鏡頭鎖閉嘴；要唱的鏡頭用專門對嘴並以 SyncNet 驗收；不要一時唱一時閉嘴。（說得太急、換班、Spark）
5. **人物身份以一張核准近景為準，用 ArcFace 量化，不靠肉眼；絕不以重畫角色的方式造新機位。**（說得太急、Spark、算了吧）
6. **場景先鎖一個有生活感的主景，其他角度從同一主景衍生，並跨角度逐區核對物件。**（不可說、光。可見、換班）
7. **審查剪接處，不只審單支片段。** 相鄰兩鏡的朝向、行進方向、雨與光、同一物件是否一致。（說得太急、換班、光。可見、Spark）
8. **剪點落在唱句之間或唱句起點，句中剪點為 0。** 小節只在無唱段作剪點依據。（光。可見、說得太急；取代換班「一律小節線」，見 §E1）
9. **大量生成前先過檢查點：** 靜圖（免費）→ 全長活母帶 v0，用戶說「有感覺」→ 少量付費證明 → 換進母帶 → 用戶批准 → 才批量。（換班、光。可見；說得太急與算了吧違反此條而超支。原順序「付費證明後才剪進歌曲」已被 §E15 取代。）
10. **同一問題試三次就換做法；連續兩次同類失敗就停止同模型重試。**（換班、光。可見、Porch-Light-Low）
11. **先在已有素材裡救，再花錢。** 取乾淨區間、裁出可用背景、本地 Blender／OpenCV 修補，往往 0 點就解決。（說得太急救回、Spark、換班、光。可見）
12. **選擇要用看的、聽的，不要用讀的。** 調色給並排比較圖、環境聲給試聽、方案給成本區間。（說得太急、換班、光。可見）
13. **自動閘門只證明「有效」，不證明「選對」；人的審查優先。** 技術驗證通過≠藝術通過；看片要密集抽幀並以正常速度觀看，並說明審查的限制。（梦幻泡影、Spark、Log Out）
14. **版本一被否決就退役，**其人物、場景、動態片不得帶入新版。「部分可用」必須寫明入點、出點與功能，否則判失敗。（說得太急）
15. **提交當下就記帳，交付時結清。** 未知寫「未知」，不寫 0。（不可說、換班）

## §B 階段檢查清單

### B1 開案（0 點）
- [ ] 鎖定發佈版音訊並逐句對照歌詞筆記；腳本跟發佈版走，不跟手稿走。（光。可見音源被截、不可說無 Bridge）
- [ ] 寫 song-treatment.md：情緒命題、主線、視覺論點、母題、人物是否為主體、人物鏡比例（舞曲 60–70%、抒情 40–50%、內省 30–40%、氛圍 10–30%）。
- [ ] 由 treatment 推出 art-direction.md，含「現在／回憶」等色彩分區（§D 色調）。
- [ ] 交付外觀寫進 treatment：片頭片名、音樂後至少 1 秒留白、全片小水印；同一 EP 沿用已發佈影片的樣式。
- [ ] 預算：專案上限、證明預算、修補預留（例：1,000／100／200）；不購買點數除非明確授權。
- [ ] 一次取得「把本 MV 參考素材上傳到指定 Flow 專案」的授權。
- [ ] 查 MV 庫：`library/patterns/` 與 `attempts.jsonl` 裡同模型、同鏡頭類型的失敗代碼。

### B2 前期（靜圖 0 點）
- [ ] 主景先做滿生活感（燈、杯、書、植物），空曠留給構圖，不留給佈景。
- [ ] 從主景衍生所需角度；每張參考圖寫「ONLY as <角色>」與「Do not reproduce either composition」（模式 reference-only-as-role：184 過／48 部分／43 失敗）。
- [ ] 跨角度核對：門窗數、物件位置、視線、光向；畫外物件不搬家。同一棟樓的內外景一致。
- [ ] 人物：正面／三分之四／側面身份母版，服裝與頭身比先過；之後所有人物鏡只從這條身份鏈派生。
- [ ] 每個場景多拍一張**無人臉的空鏡或窗景**，留給剪輯作插入鏡。
- [ ] 動態起始幀：會動的東西（窗扇、門閂、懸掛物）先修成固定；已完成的動作不要放在起始幀。

### B3 動態生成（付費）
- [ ] 證明樣片跨時長範圍選（短、中、長各有代表＋最難的一個），不只選最長。
- [ ] 本地 Wan／LTX I2V 不寫運鏡；Veo 可做空鏡慢推（需寫終點）；真正的運鏡用 Blender／VACE 或後期 2.5D。
- [ ] 提示詞結尾：「No text appears. No one else appears.」空鏡加「No people.」；結尾靜鏡加「No birds, nothing passes」。
- [ ] 不唱鏡頭用閉嘴描述（「lips stay closed… breathes through the nose」）；不要寫 smile／grin／laugh／tears 這類字，連負面詞也不寫——寫了反而會出現。
- [ ] 每次提交當下記錄 job ID、報價、實扣／退款；斷線或低點數警告後先查列表與餘額再重送。
- [ ] 同一問題三次、同類失敗連兩次 → 換做法：取乾淨段、保留小瑕疵、本地修、改走 Blender。

### B4 審片
- [ ] 全解析度每 12 幀＋臉部與小人物 ≥1.5× 放大＋靜止區域漂移檢查；不用 10 幀縮圖表。
- [ ] 逐片清單：淚光／閃光、浮空痕跡、手或物件入鏡、服裝變化、腳與地面、窗中人物、布料無因擺動、嘴是否張開。
- [ ] 人物片跑 ArcFace（中位餘弦 ≥0.45 過、0.35–0.45 複查；臉 ≥90 px 才可信），並目視下巴放大圖（鬍子、年齡）。
- [ ] 每支片記錄可用區間（入點、出點、用途）；說不出用途的「部分可用」判失敗。
- [ ] 以正常速度看完整樂句，並說明自己沒做到的審查（例如沒聽聲音）。

### B5 剪輯
- [ ] 儘早剪出全長 v1，用戶意見都對著全長版給。（全長活母帶 v0 在任何付費影片之前就要有，見 §E15。）
- [ ] 剪點：唱句起點／句間空隙優先，段落邊界次之，無唱段才用小節或拍點；渲染前數句中剪點，必須為 0。
- [ ] 相鄰兩鏡：行進方向一致（或有動機地換向，經固定鏡或細節過渡）；光、曝光、亮區位置可銜接；避免構圖幾乎相同的鄰鏡（跳切）。
- [ ] 同一人物兩個近景之間插空間鏡；道具在相鄰鏡頭起始幀就要在。
- [ ] 人臉鏡原速；補時長用插入鏡，不慢放人臉；不倒放、不循環、不 setpts 拉伸。
- [ ] 同一段素材只用一次（窗／街裁切與人臉可共用同一檔，但時間段不重疊）。
- [ ] 接不上就不硬接：插一小節空景把時間讓出來。

### B6 調色與後期
- [ ] 先每鏡曝光匹配，再風格化；光線變化本身是敘事的鏡頭保留原曝光。
- [ ] 給用戶看同樣鏡頭的並排比較圖選方案，再同時間點做前後對照。
- [ ] 保留無字母帶；片名、畫面文字、字幕、水印分層最後渲染，文字在交付解析度原生燒錄。
- [ ] 放大的裁切插入鏡要量清晰度，與全畫幅鏡頭落在同一範圍（§D 放大）。

### B7 聲音
- [ ] 原曲不可替換或重生成；混音用 `amix normalize=0`，逐秒核對歌曲電平不變。
- [ ] 環境聲一律用真實錄音，下載 3–4 個候選疊在歌曲開頭給用戶試聽選擇；不合成。

### B8 交付與發佈
- [ ] 驗證：完整解碼、幀數、尺寸、音訊與母帶一致、同時間點畫面對照；ffprobe 你要上傳的那個檔。
- [ ] 發佈包 → dry run（頻道守衛＋母帶 QA）→ 私享上傳 → API 讀回 → 定時＋AI 合成聲明 → Studio 核對「AI use: Yes」與「已排程」→ 公開後發置頂留言。
- [ ] 頻道固定週三／週六 20:00（雪梨）；AEST UTC+10，10 月第一個週日後 AEDT UTC+11。
- [ ] 成本賬、CURRENT、歌曲筆記、本文件 §F 一次結清。

## §C 救回（已判失敗的 MV）

說得太急與 Spark 都證明：失敗的 MV 常常不是素材不夠，而是沒有一條線。救回順序：

1. **診斷主線**：從已審查素材裡找一條能成立的線（說得太急：一個雨夜，從家到末班車；Spark：城市醒來＋兩扇相對的窗）。
2. **刪到只剩這條線**：刪對嘴、刪人與物件互動、刪身份不一致的臉（ArcFace 量）、刪無理由的地點。
3. **只取乾淨區間**，剪點落在唱句空隙。
4. **補時長用插入鏡**：從被刪片段裁出無人臉的背景（雨窗、雨街、空候車亭）；清晰度用 30% ESRGAN＋70% Lanczos 對齊（§D 放大）。
5. **加入脈絡**：畫面文字（直排、放暗部、只在不唱的空隙）、真實環境聲。
6. **小步快跑**：每輪只改用戶點名的時間碼；每輪確認檔案時間戳、退出碼、無殘留渲染程序。

## §D 主題索引

每條一句規則＋證據；細節見 §F 案例與原始筆記。

### 概念與故事
- 歌詞負責時間與情緒意義，不是物件清單；隱喻優先，最多兩個字面錨點。
- 逐組歌詞寫出「觀眾先看到什麼、下一鏡改變什麼、剪接體現什麼關係（倒影／實物、痕跡／來源）」。（不可說湖邊屋只部分貼合）
- 人物只提供尺度時，放遠或背向 2–3 鏡；不要因為參考做了就增加出場。（不可說角色參考重做 3 次）
- 先設計景別、運鏡、畫內動作與剪接節奏，再做參考。（不可說鏡頭表重建 3 次）
- 美術世界要自洽（材質、道具）；規則是世界一致，不是禁某類物件。（算了吧金屬風車）
- 不要為了展示能力放物件；人的存在可用構圖與缺席表達。（Log Out v5 人偶、電箱被否決）
- 美學要求逐首歌定，不要把一首的規則帶到下一首。（Love Hate 沿用无所住「幾乎無人」而錯）
- 評審前先讀 treatment：刻意的極簡元素看起來可能像未完成。（Log Out 剪影被誤判後撤回）

### 場景與空間
- 色調被認可不等於場景已鎖定；所有角度從同一主景衍生。（不可說、光。可見第三次同類錯誤 I002a–d）
- 同一地點的所有鏡頭從同一張去人物的主景衍生。（換班 2:33 天台不同）
- 晝夜單向推進，天亮後不回夜景；夜景鏡要重生成，調色轉不過來。（不可說）
- 光線變化要有畫面上的成因（先放「關燈」）；懸掛物件只在有外力時動。（換班 0:38、1:31）
- 插入鏡留在已建立的空間，用同一成因串連。（不可說 43 秒空巷 → 風吹花枝→門檻→門口）
- 生成的螢幕、手機、書頁幾乎都是空白或假字：後期當圖層設計。（換班、不可說）
- 俯拍寫「camera points straight down from the ceiling at exactly 90 degrees」；車輛鏡寫「straight empty road, no curves」。

### 人物身份
- 以一張清楚的三分之四或開場近景為身份基準；不要把縮圖拼板餵給臉部適配器。
- 絕不用 Nano Banana 重畫角色來造新角度；要多角度就拍一條連續長鏡，再從中剪。（Spark「人都變形了」）
- 幀鏈接力不是身份證明；不要經背面幀交接。（Spark A5→A8 長出鬍渣、N1→N2 轉身變臉）
- ArcFace 中位餘弦 ≥0.45 過、0.35–0.45 複查、臉 ≥90 px；嵌入看不出鬍子，下巴放大仍要目視。（說得太急：巴士近景之間 0.63–0.82，被刪街景 0.32–0.57）
- 臉要從原始身份參考派生，不是從上一鏡。風格核准≠身份核准。（算了吧 C003 v2）
- FLUX 守不住局部身體／無臉構圖，改用其他模型的靜圖（still_replacements），不要放寬閘門。（Porch-Light-Low 8→4→3）
- `visible_faces` 是模型說法，不是量測；重生成不再改變結論就停。（Porch-Light-Low 第 10 景）

### 表演與對嘴
- 不唱鏡頭鎖閉嘴（模式 closed-lip-performance：85 過／52 部分／29 失敗，已證實）；同一張嘴重抽仍張開，就取閉嘴段。（換班 S31）
- 舞蹈是成人的律動：兩步、肩膀、重心轉移、腳不超過髖寬；點名禁止有氧、踢腿、跳躍；不要露齒笑。（Spark 多輪否決）
- Veo 腿部常崩：跳舞改中近景／腰部構圖。（Spark）
- Veo 聽不到歌：按拍點評分選片段窗口（1.15–1.4 為佳），把動作峰值放在重拍。（Spark）
- 背向起始幀＋律動描述會讓人轉向鏡頭：加「stays facing the same direction」。（換班 S25）
- 對嘴驗收：SyncNet LSE-C ≥4.5、且比最佳錯句誘餌高 ≥2.0、偏移 ≤6 幀；少於 1 秒的語音無法判定，記 unreviewed。臉高 <120 px 的對白都不過，對白用近景單人。
- InfiniteTalk 輸出會補滿整窗：剪到實際語音結束；雙人要明確 ref_target_masks；黑幀先查 GGUF 雜湊。
- 驅動音訊先要清楚：中文用 edge-tts，不用 kokoro（可懂度 85% vs 43%）。

### 動態與 I2V
- 本地 I2V 預設固定機位＋一個畫內動作（模式 locked-off-camera：135 過／64／29，已證實）；描述運鏡會讓模型發明空間。（无所住 scene 02 升降變屋頂）
- 空景／物件：一個成因、一個動作、「Nothing else moves」（72／44／15）。
- 窗扇先修成固定玻璃（免費），再寫「The window stays closed and still」。（不可說 U001、U003、U011）
- 提示詞描述從靜圖開始往後的動作，不要重演靜圖已完成的事。（Love Hate 5 個提示詞重演親吻）
- 起始幀的狀態會延續：布料已在揚起就會繼續揚起，要換起始幀。（Spark）
- 需要多段接力的鏡頭多數在第一段就失敗；按「時長 ≤ video_max_frames/fps」分流；「太快／太慢」交替出現代表區間是空的，不是種子不好。
- 長停頓、沉靜的片（>8 秒鏡頭）與 I2V 動態門檻不相容：走 Blender 編排路線，不縮短鏡頭。（Porch-Light-Low；Log Out 以 Blender 完成）
- I2V 失敗時讓 Blender 負責動作、靜圖負責外觀。（梦幻泡影 7 景以 Blender 修）
- 幀數網格 8n+1、尺寸 32 的倍數；16:9 只在寬度為 512 倍數時精確（512×288、1024×576、1536×864）。
- 霧、雲做成獨立圖層疊在靜止首幀上（11／0／1），不讓 I2V 重畫整格。
- 滑動玻璃門等剛體改用 2.5D 後期。（換班 0:48）

### 生成成本與證明
- 素材量＝全曲長＋剪輯餘量＋重抽損耗；省在動作複雜度，不省畫面豐富度。（不可說「3 分鐘只做 80 秒？」）
- 早期方向搖擺最貴：算了吧 1,315 點中 560 點花在放棄的方向；說得太急 1,040 點中 v16 一版 540 點、成片只用到 24%。
- 用戶意見先分流再花錢，多數可本地修。（換班 1080p 9 條意見只花 10 點）
- 外部匯入的靜圖要目視綁定、SHA-256、匯入後再雜湊；修補迴圈不得覆蓋匯入的導演指定圖。（那道彩虹因此無法完成）
- 重用媒體以內容雜湊為鍵，不以路徑或次數。
- 本地 ComfyUI：draw 前 `ensure_available()`，否則靜默改走付費；兩個 daemon 不能同時在 16 GB 卡上載 FLUX；A/B 計時前改一個輸入避開快取。

### 審查
- 先問「第一次看，哪一刻讓人不再相信？」再看技術瑕疵。（算了吧）
- 密集抽幀（§B4）：Spark 最後 41 秒被用戶找出 8 個問題，其中 6 個在已「審過」的鏡頭。
- 自動閘門通過的東西人會否決，自動否決的東西導演可以放行。（梦幻泡影第 11、09 景）
- 多個母帶都通過閘門時，選哪個是人的事；上傳前 ffprobe 實際檔案。（梦幻泡影 4 個母帶）
- 抽樣要覆蓋所有鏡頭。（Log Out 審查有 3／8 鏡沒抽到）
- 自己聽不到就說明，聲音用試聽輪由用戶判斷。

### 剪輯與連續性
- 剪點：唱句起點／句間空隙 > 段落 > 拍點（僅無唱段）；句中剪點 0。（光。可見 2 小節網格讓 52 句中 25 句被從中剪斷）
- 鏡頭長度＝樂句下限 × 節奏倍率（沉靜 1.5×、流動 1.0×、驅動 0.75×）。（梦幻泡影 3.5 秒節奏剪出 49 個碎片）
- 相鄰鏡要可銜接但不能幾乎相同（跳切）；只追相似度會變成一串跳切。（光。可見）
- 行進方向全片一致；用窗外運動方向（相位相關）定方向。（說得太急 0:22／0:30／0:32 被指出）
- 不要左右來回反打；換向經固定鏡、細節或推鏡過渡。（不可說）
- 修補要看整個樂句；修掉瑕疵後動作仍要看得懂。（算了吧 0:47、2:47）
- 補鏡要有宿主、觸發與內容，沒有通用 B-roll。
- 疊加的人物剪影要站在真實地面上，按場景尺規定大小並加接觸陰影。（Spark 9 鏡 772 幀）
- 只重算壞掉的鏡頭並拼回中間檔，核對總幀數與替換幀數。（Spark）
- 角色對角色的甩鏡：4＋4 幀、18% 位移、≤90 px 模糊，入鏡延續出鏡方向。（Spark）

### 色調與電影感
- 選方案用並排比較圖（說得太急：文字描述 A／B 選不出，看圖一眼選定）。
- 先每鏡曝光匹配（說得太急：目標平均亮度 0.165，增益 0.55–1.35），光線變化本身是敘事的鏡頭不匹配。
- 按地點分組量 CIELAB，往組目標拉 70%（55% 看不出差別），烘成每鏡 3D LUT，在唯一一次編碼前套用。（換班）
- 「現在／回憶」兩套色：現在冷夜（陰影偏青、高光膚色偏暖、飽和 0.80、S 曲線高光 0.95 收頂）；回憶暖、淡（飽和 0.72、黑位微抬）。回憶用色彩標記，不用模糊：霧化 12% 過度，4% 才對。（說得太急）
- 電影感：燈光暈（高光模糊後紅橙 screen 疊加）、0.7 px 輕柔化去掉生成影像的塑膠銳利、較粗的時間性顆粒、暗角、2.39:1 遮幅（字幕放進下黑邊）。代價：檔案變大（3 分鐘約 280–320 MB）。（說得太急）
- 不要在 AI 生成的臉上疊加移動光帶：不自然。（說得太急路燈掃光被否決）
- 單調先用剪輯（景別、動作、停頓）解決，再考慮特效；特效要有出場理由。（算了吧彩虹）
- 注意片段內逐漸的色偏。（不可說月夜）

### 文字：片名、畫面文字、字幕
- 同一 EP 沿用已發佈影片的片頭、水印、字幕樣式。（說得太急沿用光。可見：微軟正黑 118／46 px、1–5 秒、右下雙署名水印）
- 畫面文字與字幕要有兩套字體系統：畫面文字直排宋體、放在該鏡暗部空白、只在不唱的空隙；字幕橫排置底。（說得太急）
- 畫面文字提供脈絡與情緒，不重複歌詞；帶轉折的最後一句最有效。（說得太急「下一次說不在意，我想說得慢一點」）
- 生成的字一律清掉，真字用 Blender／OpenCV 按表面透視合成；表面文字不取代字幕。（不可說、換班）
- 字幕沿用發佈版時序，不以不穩定的 ASR 改時序；雙語用旗標切換，核對行數不變。
- 本機 ffmpeg drawtext 會 segfault：用 ass 濾鏡或 PIL 渲染 PNG 疊加。

### 聲音
- 原曲不可替換；比較兩個音訊版本用相位不變的 log-mel，不用雜湊或波形相關。
- 環境聲用真實錄音（Pixabay 可商用免署名，頁面 HTML 內有 cdn 連結），3–4 個候選疊在歌曲開頭讓用戶試聽；合成雨聲聽起來是水流（峰度 5.6，真雨 14–24）；稀疏的敲窗雨「不是一聽就像下雨」；最後選穩定的全頻雨，−31 dBFS，只放前奏與片尾。（說得太急）
- 驗證環境聲是否混入要看高頻段能量，平均響度幾乎不變。

### 放大與交付
- 生成時就用能負擔的最高解析度；Lanczos 放大到交付尺寸；AI 超分不會增加真細節。
- 裁切放大的插入鏡用 30% 4xRealisticRescaler＋70% Lanczos：全畫幅鏡水平梯度 2.6–4.0，純 Lanczos 裁切約 2.7（有壓縮塊），純 ESRGAN 約 5.4（50% 在暗街景出現手繪感，NMKD 出現交叉網紋）。（說得太急）
- 運動補償慢放（minterpolate）只用於近乎靜止的環境鏡、速度 ≥0.72，並全解析度檢查插值幀；不要慢放人臉或行走。（說得太急；換班 S08 3.3× 是例外，見 §E2）
- 全片 24 fps、整數幀；渲染幀序列不放 vault。
- 給手機分享另壓 <30 MiB 版本（950 kbps 兩遍約 25 MB）。

### 發佈
- `scripts/youtube_push_song.py`：只允許私享；公開走排程或 Studio。token 失效（invalid_grant）要用戶跑 `python scripts/youtube_auth.py --profile music`。
- `videos.update(part=status)` 帶 `publishAt`（UTC）與 `containsSyntheticMedia: true`，其他 status 欄位照原值帶上；讀回看不到 AI 旗標，要到 Studio 確認。
- 縮圖用片頭片名畫面、PNG、<2 MB；歌詞已燒入時不放 .srt。
- 發佈一支影片的授權不延伸到其他影片。

### 工具與流程
- Flow 介面陷阱：重新整理後設定會跳回 Video 720p 8 秒或 x2（雙倍扣點）、Pro 變回 Nano Banana 2；JS click 不會送出；視窗隱藏會凍結頁面；編輯後的素材沿用舊檔名（Spark 因此用錯首尾幀損失 10 點）；下載以雜湊核對。
- Chrome 視窗隱藏時不要 zoom；確認參考圖真的附在輸入框。
- 背景渲染的完成通知可能早於實際完成：驗證檔案時間戳、退出碼、無殘留 ffmpeg。（說得太急）
- Windows：cv2 imread／imwrite 遇中文路徑靜默失敗，用 imdecode／imencode。

## 《算了吧》（2026-09-12 整理）

本文件是既有 MV workflow 的人工製作與驗收參考，不新增渲染管線，也不代表這些判斷已由程式自動執行。案例來自《算了吧》的用戶逐輪回饋，以及 v80 的交付、驗證和剪輯紀錄；不把「已發佈」等同於每個藝術細節都獲得單獨認可。

## 場景多角度參考（2026-09-13，《不可說》試製）

色調認可不等於場景已鎖定。本次參考圖曾出現門窗在不同角度落到不同牆面、反打把椅子移位的問題；用戶也指出室內過空。先把主場景的陳設與生活感做好，再從同一空間衍生所需角度，避免把仍在修改的空房間批量動畫化。新版室內與院落仍是待確認候選，不能把這條流程更新當作圖片已獲批准。

此經驗已納入 [標準流程的多角度場景參考](MV-GENERATION-WORKFLOW.md#multi-angle-scene-references)：主視角與陳設鎖定 → 所需反打／側面／室內外參考 → 跨角度空間核對 → 個別原圖與來源版本鎖定 → 動態樣片 → 批量生成。比較圖板用於審查，生成使用乾淨的單張參考。家具在畫外不代表可以搬到另一面；相同提示詞也不能證明是同一間房。

這是每首歌按鏡頭需要執行的製作要求，不要求所有作品採用《不可說》的家具、色調或場景密度，也不表示程式已自動檢查空間一致性。

## 1. 最重要的取捨

**優先順序：歌曲情緒與鏡頭關係 → 動作可信度 → 觀看節奏 → 畫面與字體設計 → 清晰度與交付。** 技術檢查另外執行，不能取代觀看。

這次用戶指出的關鍵問題是手摸樹枝的 AI 痕跡、河邊灰色金屬風車的突兀感，以及不連續的跑動。審查如果只列解析度、音畫同步或一般瑕疵，就沒有抓住影片為何令人出戲。

審查先問「第一次觀看，哪一刻讓人不再相信這個動作或不明白為何切到這裡？」每項問題寫成：版本、時間、可見現象、對觀看的影響、最小修法、驗收片段。先處理最傷害理解和情緒的三項。

## 2. 素材從生成開始就要能剪

不要只按歌詞長度生成一段影片。對重要動作，提前準備相容的主鏡頭和必要細節；素材餘量優先給接觸、轉身、跳躍與換向，穩定環境鏡頭不必等額增加。

手碰物體、起跳落地、身體翻轉，都是本片暴露出的風險。先用短樣片確認動作能成立，再投入全長；生成失敗時，保留敘事目的、簡化表演，而不是反覆要求更複雜的肢體動作。需要精確物理或指定轉身時，考慮可控制的動畫與分鏡，不能預設自由生成一定能完成。

逐片記錄「實際素材」，不能把 prompt 當作觀察結果。既有 montage 參考已有完整 shot-state ledger；以下是開案表格的最小使用視圖，不另建一套 API schema：

| 欄位 | 必須讓下一位剪輯者知道什麼 |
|---|---|
| 素材識別 | shot ID、原檔路徑與 hash、尺寸、原生 fps |
| 選用區間 | 原片 in/out 幀、時間線 in/out 幀；明定區間端點慣例 |
| 行進與朝向 | 畫面左／右／朝鏡／遠離／原地／轉向；身體朝向與視線分開記 |
| 首尾狀態 | 邊界幀、姿勢、动作階段、著地／懸空、可見支撐腳、位置、景別 |
| 動作速度 | 實際感受到的快慢、加速與減速；與鏡頭移動分開 |
| 連續性 | 衣物、道具材質與位置、光線、地理、母題狀態 |
| 可用性 | 可用區間、不可用區間、缺陷與信心；遮擋看不清就標未知 |
| 剪輯理由 | 承接前鏡什麼、交給下鏡什麼、歌曲提示、連續或有意斷開 |
| 變換 | 裁切、縮放、鏡像、變速；變換後重新核對方向與狀態 |

一個檔案含轉身或內部剪接，要分段標記。無人物不代表無方向：腳步、紙張、水流和視線仍可能把注意力帶往某一側。

## 3. 修接點，不能把主要動作剪沒了

| 本片回饋 | 下次採用的判斷 |
|---|---|
| 約 0:47，先懸空再落下 | 刪除錯誤前段，尋找可讀的動作入口；不是所有跳躍都必須從站立開始 |
| 約 1:17，架起雙手很怪 | 檢查準備動作是否必要，優先保留可信的表演區間 |
| 約 1:43，跳水坑突然慢下來 | 先核對原速、動作節點與歌曲，再決定節奏；不要用慢動作填時間 |
| 約 2:47，背面直接變正面 | 切開變形接點，在相容動作階段銜接；保住起跳、騰空或落地中讓人辨識事件的關鍵證據 |
| 插入 1.5 秒腳步後看不出跳躍 | 技術遮蓋成功不代表修剪成功；修後必須仍看得懂原本想表達的動作 |
| 插入草葉顯得突然 | 補鏡需要同場物件、運動、視線或情緒的動機；不能只因為素材乾淨就插入 |

以上時間屬用戶當時觀看的版本，不直接套用到 v80。追蹤問題時同時記 stable shot ID，避免重剪後時間碼漂移。

每次修補同時看 A/B 的整個樂句，包含前後鏡頭。不要只看修掉的幾幀。先嘗試改切點、相容機位或短細節；若無可用 coverage，改成可理解的省略，或換掉整個動作。不能宣稱剪輯創造了素材中不存在的連續轉身。

同向跑動有利於持續前進；反向並非禁忌，但要對應猶豫、衝突、段落轉折或重新建立空間。不要事後替每次意外換向補一個情緒理由。對灰色金屬風車的教訓是材質和世界觀需一致，不是所有 MV 都禁止金屬物件。

## 4. 歌詞貼紙：先定動作語言，再铺全片

本片已表達的偏好：標籤有紙感、較細的框、背景色隨情緒變化、輕微呼吸、貼上與揭下，以及不同位置交接。這是本片可沿用的風格選項，下一首仍從歌曲出發。

字幕的語意單位、閱讀時間與動畫時間要一起設計。不要機械地一行一張，也不要拆到每個字都在搶注意力。若拆分後沒有足夠時間讀清楚、再完成揭下，就合併；若長句擠滿畫面或阻礙節拍，就按自然語意拆開。

每張標籤至少排出四段時間：貼入、清楚可讀、揭離、離場。記錄實際可讀區間，不能把背面朝向觀眾的時間也算閱讀時間。A 揭下時，B 可以在另一位置貼上，但避免同時爭奪視線或遮住臉、手和關鍵動作。

| 視覺要求 | 驗收方式 |
|---|---|
| 貼上 | 先局部接觸，再逐漸貼平；不是整片平移加淡入 |
| 揭下 | 從角或邊逐步離面，有捲曲與尚未離開的接觸區；不是整張硬板翻轉 |
| 紙背 | 與紙張一致的暖白／纖維質感，受光後可變暗；不長時間露出一整塊灰背 |
| 光影 | 局部高光沿捲邊移動，陰影隨離面距離變化；亮度不能蓋掉字 |
| 呼吸 | 在穩定可讀期保留輕微、緩慢的變化；不等於抖動或不停縮放 |
| 配色與框 | 保留標籤背景色變化，框線在交付尺寸不搶字；不能把「細框」誤做成純黑字 |
| 場景貼附 | 只挑適合的牆、玻璃或地面，核對透視、追蹤、陰影及人物遮擋；漂移時撤回或修正 |

先做一個完整樂句的循環樣片，展示貼入、閱讀、揭下和下一張交接，再推到全片。參考影片要拆解接觸點、彎曲、速度曲線與陰影；看過參考不等於成品已重現其效果。

## 5. 後期與清晰度要分開驗收

先統一素材的曝光、冷暖和對比，再設計段落間緩慢的情緒變化。主歌稍冷、副歌轉暖、尾聲柔金色是本片方案，不是通用規定。畫面單調時，先調整景別、動作種類、停頓和段落能量，不先堆特效。

彩虹等尾聲效果要有出場理由，並與環境的遮擋、光線及水面相容。局部、不完整的虹光可能更自然；反射不能是一條同樣清楚的彩虹複製品。以整段觀看效果決定保留，不能只用漂亮截圖驗收。

清晰度按以下順序處理：

1. 回到原始片，減少從已壓縮交付檔再裁切、再編碼。
2. 在裁切前評估有效像素。本片曾指出 568×320 的腳步裁切被放大；1080p 容器本身不證明細節充足。
3. 若測試超分，選含臉、頭髮、草葉及運動的短片做同尺寸、同速度 A/B。檢查閃爍、假紋理和邊緣光暈，不只看單幀。
4. 歌詞、框線、捲紙和彩虹在交付尺寸重新合成，避免連已燒入的文字一起放大。
5. 最後輕量銳化；無法恢復的細節，就減少裁切、換素材或調整景別。

Real-ESRGAN 動畫模型在對話中是候選方案；本次整理未取得足以證明其全片提升幅度的對照報告，不將它列為已驗證的固定解法。精確模型、參數與成本留給下一次有證據的短片測試。

## 6. 下一個 MV 的執行節點

| 節點 | 交付與過關條件 |
|---|---|
| 開案 | 選定原曲、完整聽歌、情緒弧線、視覺論點、當前頻道名與署名；不沿用過期品牌 |
| 全曲粗剪 | 先有全長 living master，確認整體意義、能量起伏及鏡頭關係，再生成大批素材 |
| 風險樣片 | 先證明最難的接觸／跳躍／轉身與所需剪輯 coverage；不以模型出檔作成功 |
| 素材入庫 | 實看動作、標方向與首尾狀態、綁定可用區間及 hash；拒絕素材不能在後續自動回流 |
| 主體精剪 | 無聲看連續性，再配原曲看節奏；以完整樂句驗收每個修補 |
| 字幕與後期 | 先通過代表樣片，再逐段套用；維持可讀性、表演和情緒優先 |
| 全片審查 | 先列最影響觀看的問題，再看局部瑕疵；核對片頭、角落水印、音樂結束與餘韻 |
| 交付發佈 | 原音、幀數、尺寸、解碼、首尾檢查；記錄選定版本及平台可見性，依當次授權私人或公開 |

音樂結束後留畫面是有用的尾聲選項，本片採約 3 秒停留加約 0.75 秒淡黑。下次按尾音與情緒決定長度，不能擅自延長或替換歌曲。

每次完成有意義的修改，更新同一份交付索引：當前完整版本、待解問題、素材清單、驗收證據、下一步。版本號、預覽和局部修補檔不能代替「哪一個才是可交付完整版」的明確標記。

### 流程上的教訓

- **上傳授權要在開案時一次取得。** 「獨立完成整個 MV」沒有被 Codex 自動審核接受為上傳授權，卡了三輪 goal，直到 Kevin 明確寫出「允許把本 MV 的所有生成參考素材上傳至目前 Google Flow 專案」。
- **提交當下就記帳。** 事後只能恢復製作承諾，590 點裡有 580 點的實扣與退款仍無法核對。
- **全片 v1 要早出。** 每格有候選就先剪全長，Kevin 的每一條品質回饋都是對著全長版本給的。
- **保留無字母帶。** 片名、字幕、水印分層最後渲染。這讓 720p 素材能以 lanczos 放大後，在 1080p 原生重燒文字（v11），不把 720p 燒錄字一起放大。
- **字幕沿用發佈版時序。** 兩個本地 ASR 對四句疑點的判斷互相矛盾，因此不改時序。

### 流程上的教訓

- **同一個生成問題三次就換做法。** S31 張嘴呼吸重抽三次都一樣，改取閉唇段（`换班:video:S31:1`、`:2` 逾時、`:3`）。S06 便簽翹起兩次，改取平靜段放慢（`换班:video:S06:1`、`:2`）。S36 玻璃倒影修圖兩次去不掉，就保留（`换班:still:B-S36-start-r1:1`、`换班:still:B-S36-start-r2:1`）。
- **場景內真文字：Blender 算字，OpenCV 貼上。** Blender 5 headless 把手寫字算成透明貼圖，每個字加隨機偏移、大小和旋轉；OpenCV 用單應性變換貼到畫面。
  - 追蹤：固定鏡用四角定位；焦點會呼吸的鏡頭用 ECC；有手遮擋的用 KLT＋RANSAC。
  - 墨色用乘法疊上去；每幀用畫面清晰度決定字的模糊程度；用便簽本身的顏色做遮擋，手、毯子和光斑經過時自然蓋住字。
  - 在 lanczos 放大後的 1080p 畫面上貼字，字是原生 1080p。
- **連戲比指定清單重要。** Kevin 指定四個鏡頭寫字，同一張便簽出現的其他四個鏡頭（S22、S30、S36、S37）也一併寫上，並在報告說明。
- **Windows 陷阱：** cv2.imread／imwrite 遇到中文路徑會靜默失敗，要用 imdecode／imencode；findTransformECC 的模板和輸入必須同尺寸；本機 ffmpeg 的 drawtext 會 segfault，但 ass 濾鏡正常。
- **Flow 介面：**
  - 素材選單點選項後不一定會自動關，要確認縮圖已出現在輸入框上方才送出。
  - 選單沒開時不要盲點「Add to prompt」，會把頁面點壞，只能重新整理。
  - 頁首左上是專案名稱輸入框，搜尋框要用 aria-label="Search" 找。
  - 失敗的 tile 仍顯示下載鈕，下載前先查該列有沒有 Failed。

- **1080p 意見的修法（Kevin「優先用blender解決」）：** 一輪 9 條意見只花 10 點（S08），其餘全在本機。
  - 螢幕／手機：Blender 算無字 UI → `composite_note_text.py` 的 `screen` 圖層（乘法，`fade_luma` 讓關機時內容消失）。唱片封套用 `replace` 圖層（按原紙面亮度上色）。同一鏡多個圖層依序疊，遮擋判斷一律看原始畫面，後一層才蓋得住前一層。
  - 旋轉的手機、重疊的兩張封套：追一個軸對齊的代理框，再用 `derive_track.py` 把每幀仿射套到真實四角；直接追旋轉四角會被角點排序打亂。
  - 追蹤起始幀要和量四角的那一幀是同一幀。S31 第一次在別的時間點量四角，封套差了將近 20 像素。
  - 2.5D 靜圖動態（`plate_motion.py`）：天空用邊緣圖＋flood fill 找出來，屋頂下方先 inpaint 延伸再漂移，建築就不會被拖進去；天空裡的小黑點（鳥）一起修掉。
- **重生成滿三次：取乾淨段做運動補償慢放。** S08 第 3 次（`换班:video:S08:3`）只有前 1.75 秒可用（之後推鏡加速、嘴張開、鏡頭滑出人物）。取這段用 minterpolate（mci）慢 3.3 倍填滿 5.64 秒，逐 6 幀檢查臉部沒有扭曲。**（例外，不作先例：不慢放人臉與行走，見 §E2。）**
- **Chrome 擴充回報「未連線」時，JS 可能其實已經跑完。** 這次附參考＋填提示全部完成了，重試前先讀輸入框狀態，否則會重複附圖。
- **Flow 幀選單：滑鼠懸停不會換預覽，要點選項才會。** 預覽圖一直停在第一個選項，差點把舊首幀當成新首幀送去生成影片。點選項、看預覽確認是哪一張，再按「Add to prompt」。
- **全片調色要有前後對照。** 同一時間點的調色前後並排成一張表再判斷；只看數字會把「看不出差別」誤當成完成。
- **交付到上傳的順序：** 驗證（幀數、完整解碼、音訊一致）→ 發布包（標題、描述、標籤、置頂留言、縮圖）→ dry run（頻道守衛＋母帶 QA）→ 私享上傳 → API 讀回 → 定時與 AI 聲明 → Studio 頁面核對。
- **定時發佈與 AI 合成聲明可以用 API 設。** `videos.update(part=status)` 帶 `publishAt`（UTC）和 `containsSyntheticMedia: true`，其餘 status 欄位照原值帶上。讀回時 `containsSyntheticMedia` 不會出現，所以要到 Studio 頁面確認「AI use: Yes」。置頂留言要等影片公開後才能發。
- **發佈時間照頻道固定日。** 頻道計畫是週三、週六 20:00（雪梨）。AEST 是 UTC+10，10 月第一個週日後 AEDT 是 UTC+11，換算 `publishAt` 時要看當天時區。
- **給朋友看的分享版另外壓。** 720p 字幕版 CRF 22 約 41 MB；兩遍 950 kbps 約 25 MB，字幕仍清楚。傳給手機端的檔案要在 30 MiB 以下。
- **成本賬交付時一次補齊。** 狀態、交付日期、Claude Code 用量（會話日誌按 message id 去重重算）、機器耗時、總帳一行都要更新；未知項保留「未知」，不寫 0。
