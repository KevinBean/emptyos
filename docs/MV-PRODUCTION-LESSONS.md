# MV 製作經驗：從《算了吧》到下一個項目

整理日期：2026-09-12。用途：開案、素材驗收、重剪、動態歌詞設計與交付。

本文件是既有 MV workflow 的人工製作與驗收參考，不新增渲染管線，也不代表這些判斷已由程式自動執行。案例來自《算了吧》的用戶逐輪回饋，以及 v80 的交付、驗證和剪輯紀錄；不把「已發佈」等同於每個藝術細節都獲得單獨認可。

行內的生成記錄編號（`專案:階段:鏡頭:次數`）對應 vault 的 MV 庫 `10_Projects/YouTube-Music-Channel/library/attempts.jsonl`；可重複使用的提示詞寫法與它們的成功／失敗數在 `library/patterns/`。

## 場景多角度參考（2026-09-13，《不可說》試製）

色調認可不等於場景已鎖定。本次參考圖曾出現門窗在不同角度落到不同牆面、反打把椅子移位的問題；用戶也指出室內過空。先把主場景的陳設與生活感做好，再從同一空間衍生所需角度，避免把仍在修改的空房間批量動畫化。新版室內與院落仍是待確認候選，不能把這條流程更新當作圖片已獲批准。

此經驗已納入 [標準流程的多角度場景參考](MV-GENERATION-WORKFLOW.md#multi-angle-scene-references)：主視角與陳設鎖定 → 所需反打／側面／室內外參考 → 跨角度空間核對 → 個別原圖與來源版本鎖定 → 動態樣片 → 批量生成。比較圖板用於審查，生成使用乾淨的單張參考。家具在畫外不代表可以搬到另一面；相同提示詞也不能證明是同一間房。

這是每首歌按鏡頭需要執行的製作要求，不要求所有作品採用《不可說》的家具、色調或場景密度，也不表示程式已自動檢查空間一致性。

## 1. 最重要的取捨

**優先順序：歌曲情緒與鏡頭關係 → 動作可信度 → 觀看節奏 → 畫面與字體設計 → 清晰度與交付。** 技術檢查另外執行，不能取代觀看。

這次用戶指出的關鍵問題是手摸樹枝的 AI 痕跡、河邊灰色金屬風車的突兀感，以及不連續的跑動。審查如果只列解析度、音畫同步或一般瑕疵，就沒有抓住影片為何令人出戲。

審查先問「第一次觀看，哪一刻讓人不再相信這個動作或不明白為何切到這裡？」每項問題寫成：版本、時間、可見現象、對觀看的影響、最小修法、驗收片段。先處理最傷害理解和情緒的三項。

## 2. 素材從生成開始就要能剪

不要只按歌詞長度生成一段影片。對重要動作，提前準備相容的主鏡頭和必要細節；素材餘量優先給接觸、轉身、跳躍與換向，穩定環境鏡頭不必等額增加。

手碰物體、起跳落地、身體翻轉，都是本片暴露出的風險。先用短樣片確認動作能成立，再投入全長；生成失敗時，保留敘事目的、簡化表演，而不是反覆要求更複雜的肢體動作。需要精確物理或指定轉身時，考慮可控制的動畫與分鏡，不能預設自由生成一定能完成。

逐片記錄「實際素材」，不能把 prompt 當作觀察結果。既有 montage 參考已有完整 shot-state ledger；以下是開案表格的最小使用視圖，不另建一套 API schema：

| 欄位 | 必須讓下一位剪輯者知道什麼 |
|---|---|
| 素材識別 | shot ID、原檔路徑與 hash、尺寸、原生 fps |
| 選用區間 | 原片 in/out 幀、時間線 in/out 幀；明定區間端點慣例 |
| 行進與朝向 | 畫面左／右／朝鏡／遠離／原地／轉向；身體朝向與視線分開記 |
| 首尾狀態 | 邊界幀、姿勢、动作階段、著地／懸空、可見支撐腳、位置、景別 |
| 動作速度 | 實際感受到的快慢、加速與減速；與鏡頭移動分開 |
| 連續性 | 衣物、道具材質與位置、光線、地理、母題狀態 |
| 可用性 | 可用區間、不可用區間、缺陷與信心；遮擋看不清就標未知 |
| 剪輯理由 | 承接前鏡什麼、交給下鏡什麼、歌曲提示、連續或有意斷開 |
| 變換 | 裁切、縮放、鏡像、變速；變換後重新核對方向與狀態 |

一個檔案含轉身或內部剪接，要分段標記。無人物不代表無方向：腳步、紙張、水流和視線仍可能把注意力帶往某一側。

## 3. 修接點，不能把主要動作剪沒了

| 本片回饋 | 下次採用的判斷 |
|---|---|
| 約 0:47，先懸空再落下 | 刪除錯誤前段，尋找可讀的動作入口；不是所有跳躍都必須從站立開始 |
| 約 1:17，架起雙手很怪 | 檢查準備動作是否必要，優先保留可信的表演區間 |
| 約 1:43，跳水坑突然慢下來 | 先核對原速、動作節點與歌曲，再決定節奏；不要用慢動作填時間 |
| 約 2:47，背面直接變正面 | 切開變形接點，在相容動作階段銜接；保住起跳、騰空或落地中讓人辨識事件的關鍵證據 |
| 插入 1.5 秒腳步後看不出跳躍 | 技術遮蓋成功不代表修剪成功；修後必須仍看得懂原本想表達的動作 |
| 插入草葉顯得突然 | 補鏡需要同場物件、運動、視線或情緒的動機；不能只因為素材乾淨就插入 |

以上時間屬用戶當時觀看的版本，不直接套用到 v80。追蹤問題時同時記 stable shot ID，避免重剪後時間碼漂移。

每次修補同時看 A/B 的整個樂句，包含前後鏡頭。不要只看修掉的幾幀。先嘗試改切點、相容機位或短細節；若無可用 coverage，改成可理解的省略，或換掉整個動作。不能宣稱剪輯創造了素材中不存在的連續轉身。

同向跑動有利於持續前進；反向並非禁忌，但要對應猶豫、衝突、段落轉折或重新建立空間。不要事後替每次意外換向補一個情緒理由。對灰色金屬風車的教訓是材質和世界觀需一致，不是所有 MV 都禁止金屬物件。

## 4. 歌詞貼紙：先定動作語言，再铺全片

本片已表達的偏好：標籤有紙感、較細的框、背景色隨情緒變化、輕微呼吸、貼上與揭下，以及不同位置交接。這是本片可沿用的風格選項，下一首仍從歌曲出發。

字幕的語意單位、閱讀時間與動畫時間要一起設計。不要機械地一行一張，也不要拆到每個字都在搶注意力。若拆分後沒有足夠時間讀清楚、再完成揭下，就合併；若長句擠滿畫面或阻礙節拍，就按自然語意拆開。

每張標籤至少排出四段時間：貼入、清楚可讀、揭離、離場。記錄實際可讀區間，不能把背面朝向觀眾的時間也算閱讀時間。A 揭下時，B 可以在另一位置貼上，但避免同時爭奪視線或遮住臉、手和關鍵動作。

| 視覺要求 | 驗收方式 |
|---|---|
| 貼上 | 先局部接觸，再逐漸貼平；不是整片平移加淡入 |
| 揭下 | 從角或邊逐步離面，有捲曲與尚未離開的接觸區；不是整張硬板翻轉 |
| 紙背 | 與紙張一致的暖白／纖維質感，受光後可變暗；不長時間露出一整塊灰背 |
| 光影 | 局部高光沿捲邊移動，陰影隨離面距離變化；亮度不能蓋掉字 |
| 呼吸 | 在穩定可讀期保留輕微、緩慢的變化；不等於抖動或不停縮放 |
| 配色與框 | 保留標籤背景色變化，框線在交付尺寸不搶字；不能把「細框」誤做成純黑字 |
| 場景貼附 | 只挑適合的牆、玻璃或地面，核對透視、追蹤、陰影及人物遮擋；漂移時撤回或修正 |

先做一個完整樂句的循環樣片，展示貼入、閱讀、揭下和下一張交接，再推到全片。參考影片要拆解接觸點、彎曲、速度曲線與陰影；看過參考不等於成品已重現其效果。

## 5. 後期與清晰度要分開驗收

先統一素材的曝光、冷暖和對比，再設計段落間緩慢的情緒變化。主歌稍冷、副歌轉暖、尾聲柔金色是本片方案，不是通用規定。畫面單調時，先調整景別、動作種類、停頓和段落能量，不先堆特效。

彩虹等尾聲效果要有出場理由，並與環境的遮擋、光線及水面相容。局部、不完整的虹光可能更自然；反射不能是一條同樣清楚的彩虹複製品。以整段觀看效果決定保留，不能只用漂亮截圖驗收。

清晰度按以下順序處理：

1. 回到原始片，減少從已壓縮交付檔再裁切、再編碼。
2. 在裁切前評估有效像素。本片曾指出 568×320 的腳步裁切被放大；1080p 容器本身不證明細節充足。
3. 若測試超分，選含臉、頭髮、草葉及運動的短片做同尺寸、同速度 A/B。檢查閃爍、假紋理和邊緣光暈，不只看單幀。
4. 歌詞、框線、捲紙和彩虹在交付尺寸重新合成，避免連已燒入的文字一起放大。
5. 最後輕量銳化；無法恢復的細節，就減少裁切、換素材或調整景別。

Real-ESRGAN 動畫模型在對話中是候選方案；本次整理未取得足以證明其全片提升幅度的對照報告，不將它列為已驗證的固定解法。精確模型、參數與成本留給下一次有證據的短片測試。

音樂結束後留畫面是有用的尾聲選項，本片採約 3 秒停留加約 0.75 秒淡黑。下次按尾音與情緒決定長度，不能擅自延長或替換歌曲。

每次完成有意義的修改，更新同一份交付索引：當前完整版本、待解問題、素材清單、驗收證據、下一步。版本號、預覽和局部修補檔不能代替「哪一個才是可交付完整版」的明確標記。

### 流程上的教訓

- **上傳授權要在開案時一次取得。** 「獨立完成整個 MV」沒有被 Codex 自動審核接受為上傳授權，卡了三輪 goal，直到 Kevin 明確寫出「允許把本 MV 的所有生成參考素材上傳至目前 Google Flow 專案」。
- **提交當下就記帳。** 事後只能恢復製作承諾，590 點裡有 580 點的實扣與退款仍無法核對。
- **全片 v1 要早出。** 每格有候選就先剪全長，Kevin 的每一條品質回饋都是對著全長版本給的。
- **保留無字母帶。** 片名、字幕、水印分層最後渲染。這讓 720p 素材能以 lanczos 放大後，在 1080p 原生重燒文字（v11），不把 720p 燒錄字一起放大。
- **字幕沿用發佈版時序。** 兩個本地 ASR 對四句疑點的判斷互相矛盾，因此不改時序。

### 流程上的教訓

- **同一個生成問題三次就換做法。** S31 張嘴呼吸重抽三次都一樣，改取閉唇段（`换班:video:S31:1`、`:2` 逾時、`:3`）。S06 便簽翹起兩次，改取平靜段放慢（`换班:video:S06:1`、`:2`）。S36 玻璃倒影修圖兩次去不掉，就保留（`换班:still:B-S36-start-r1:1`、`换班:still:B-S36-start-r2:1`）。
- **場景內真文字：Blender 算字，OpenCV 貼上。** Blender 5 headless 把手寫字算成透明貼圖，每個字加隨機偏移、大小和旋轉；OpenCV 用單應性變換貼到畫面。
  - 追蹤：固定鏡用四角定位；焦點會呼吸的鏡頭用 ECC；有手遮擋的用 KLT＋RANSAC。
  - 墨色用乘法疊上去；每幀用畫面清晰度決定字的模糊程度；用便簽本身的顏色做遮擋，手、毯子和光斑經過時自然蓋住字。
  - 在 lanczos 放大後的 1080p 畫面上貼字，字是原生 1080p。
- **連戲比指定清單重要。** Kevin 指定四個鏡頭寫字，同一張便簽出現的其他四個鏡頭（S22、S30、S36、S37）也一併寫上，並在報告說明。
- **Windows 陷阱：** cv2.imread／imwrite 遇到中文路徑會靜默失敗，要用 imdecode／imencode；findTransformECC 的模板和輸入必須同尺寸；本機 ffmpeg 的 drawtext 會 segfault，但 ass 濾鏡正常。
- **Flow 介面：**
  - 素材選單點選項後不一定會自動關，要確認縮圖已出現在輸入框上方才送出。
  - 選單沒開時不要盲點「Add to prompt」，會把頁面點壞，只能重新整理。
  - 頁首左上是專案名稱輸入框，搜尋框要用 aria-label="Search" 找。
  - 失敗的 tile 仍顯示下載鈕，下載前先查該列有沒有 Failed。

- **1080p 意見的修法（Kevin「優先用blender解決」）：** 一輪 9 條意見只花 10 點（S08），其餘全在本機。
  - 螢幕／手機：Blender 算無字 UI → `composite_note_text.py` 的 `screen` 圖層（乘法，`fade_luma` 讓關機時內容消失）。唱片封套用 `replace` 圖層（按原紙面亮度上色）。同一鏡多個圖層依序疊，遮擋判斷一律看原始畫面，後一層才蓋得住前一層。
  - 旋轉的手機、重疊的兩張封套：追一個軸對齊的代理框，再用 `derive_track.py` 把每幀仿射套到真實四角；直接追旋轉四角會被角點排序打亂。
  - 追蹤起始幀要和量四角的那一幀是同一幀。S31 第一次在別的時間點量四角，封套差了將近 20 像素。
  - 2.5D 靜圖動態（`plate_motion.py`）：天空用邊緣圖＋flood fill 找出來，屋頂下方先 inpaint 延伸再漂移，建築就不會被拖進去；天空裡的小黑點（鳥）一起修掉。
- **重生成滿三次：取乾淨段做運動補償慢放。** S08 第 3 次（`换班:video:S08:3`）只有前 1.75 秒可用（之後推鏡加速、嘴張開、鏡頭滑出人物）。取這段用 minterpolate（mci）慢 3.3 倍填滿 5.64 秒，逐 6 幀檢查臉部沒有扭曲。
- **Chrome 擴充回報「未連線」時，JS 可能其實已經跑完。** 這次附參考＋填提示全部完成了，重試前先讀輸入框狀態，否則會重複附圖。
- **Flow 幀選單：滑鼠懸停不會換預覽，要點選項才會。** 預覽圖一直停在第一個選項，差點把舊首幀當成新首幀送去生成影片。點選項、看預覽確認是哪一張，再按「Add to prompt」。
- **全片調色要有前後對照。** 同一時間點的調色前後並排成一張表再判斷；只看數字會把「看不出差別」誤當成完成。
